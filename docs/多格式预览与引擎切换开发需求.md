# 多格式预览与引擎切换 — 开发需求

> 版本：v0.1  
> 日期：2026-09-30  
> 状态：方案已选定，分阶段实现  
> 关联：`docs/预览窗格.md`、`MarkdownPreview.Handler`、`MarkdownEditorControl`

---

## 1. 背景与目标

### 1.1 现状

| 能力 | 现状 |
|------|------|
| 资源管理器预览窗格 | 仅 `.md`；引擎由 `%LocalAppData%\MarkdownContextViewer\preview-engine.txt` 决定，**窗格内无法切换** |
| 主程序编辑预览 | `WebBrowser` / `WinFormsMarkdownView`；引擎切换在主菜单「查看」 |
| JSON / XML | **不支持** |

### 1.2 目标

1. **预览窗格内**可切换 Web / WinForms，并标明性能差异。  
2. 主程序与预览窗格**共用同一引擎设置**，切换即时生效。  
3. 规划扩展到 **JSON、XML** 等文本类型；选定架构后分阶段落地。

### 1.3 非目标（首版）

- 完整插件市场 / 热插拔第三方 DLL（可留扩展点）  
- PDF、图片、Office 等非纯文本预览  
- 替换现有 SharpShell COM 宿主

## 2. 引擎对比（给用户的标注依据）

| 维度 | Web（WebView2 / WebBrowser） | WinForms（RichTextBox） |
|------|------------------------------|-------------------------|
| **启动速度** | 较慢（需初始化浏览器内核） | **更快** ★推荐轻量场景 |
| **大文件滚动** | 一般依赖 DOM | **更轻、更稳** ★ |
| **Markdown 还原度** | **高**（HTML/CSS/表格/代码块）★ | 低（标题/粗体/列表近似） |
| **JSON / XML** | 可用 HTML 着色，开销更大 | 树控 + 文本，**更合适** ★ |
| **依赖** | WebView2 Runtime（Handler） | 无额外运行时 |
| **内存** | 偏高 | **更低** ★ |

**产品文案建议（写在按钮/Tooltip）：**

- `Web（还原度高）` — 适合看 Markdown 排版效果  
- `WinForms（更快更省）` — 适合大文件、快速浏览、JSON/XML

默认引擎：仍建议 **Web**（保证 Markdown 观感）；用户可切到 WinForms 追求性能。

## 3. 多格式方案对比：插件 vs 进程内界面

### 3.1 方案 A：独立插件（MEF / 动态加载 DLL）

```
MarkdownPreview.Handler (宿主)
  └─ Plugins/
       ├─ MdPreview.dll
       ├─ JsonPreview.dll
       └─ XmlPreview.dll
```

| 优点 | 缺点 |
|------|------|
| 扩展解耦，第三方可贡献 | COM 预览宿主进程隔离下加载复杂 |
| 按需部署 | 版本/依赖冲突；调试成本高 |
| | 首版仅 3 种格式，投入产出比低 |

### 3.2 方案 B：原项目内增加界面 + 按扩展切换 UserControl（推荐）

```
PreviewHostControl（工具栏 + 引擎切换 + 内容区）
  └─ 按扩展名选择 IDocumentPreviewProvider
       ├─ MarkdownPreviewProvider → WebView / WinFormsMarkdownView
       ├─ JsonPreviewProvider     → TreeView + 文本（或 Web 着色）
       └─ XmlPreviewProvider      → TreeView + 文本
```

| 优点 | 缺点 |
|------|------|
| 与现有 Handler / 主程序一致，易维护 | 格式变多后程序集体积增大 |
| 一套 COM 注册可挂多个扩展名 | 不如插件「可单独卸载」 |
| 设计器可直接改各格式控件 | |
| 后期仍可抽出接口做成插件 | |

### 3.3 结论（选定）

**采用方案 B：进程内 Provider + 宿主切换视图。**

理由：

1. 预览窗格跑在 `prevhost.exe`，**插件加载/卸载不稳定**，与 SharpShell 冲突风险高。  
2. JSON/XML 与 Markdown 同属「文本结构化预览」，放同一解决方案最自然。  
3. 先定义 `IDocumentPreviewProvider`，将来若要插件，只需再做一个 `PluginPreviewLoader`，不必推翻宿主。

**不做首版插件系统；保留接口作为扩展点。**

## 4. 目标架构

### 4.1 核心接口（进程内）

```csharp
interface IDocumentPreviewProvider
{
    string Id { get; }                    // "markdown" / "json" / "xml"
    string DisplayName { get; }
    IReadOnlyList<string> Extensions { get; }  // ".md", ".markdown"
    bool SupportsEngine(PreviewEngineKind kind);
    Control CreateView();                 // 可返回带双引擎的复合控件
    void Load(string filePath, string text, PreviewEngineKind engine);
}
```

### 4.2 宿主职责

`PreviewHostControl`（或扩展现有 `MarkdownPreviewControl`）：

1. 工具栏：最近 / 刷新 / **引擎切换（带性能标注）** / …  
2. 根据文件扩展名解析 Provider。  
3. 切换引擎时调用 `Load` 重渲染。  
4. 读写共享设置文件（与主程序一致）。

### 4.3 注册表（资源管理器）

首版可在同一 Handler 上增加关联：

```
.COMServerAssociation: .md, .markdown, .json, .xml
```

或分阶段：先 `.md` 完善引擎 UI，再注册 `.json` / `.xml`。

### 4.4 主程序

- `MarkdownEditorControl` 视图页增加引擎切换（与菜单同步）。  
- 后续「打开 JSON/XML」可用同一 Provider 只读预览 Tab（编辑能力另议）。

## 7. 风险与注意

| 风险 | 应对 |
|------|------|
| WebView2 在 Low IL / prevhost 初始化失败 | 已有失败提示；切换到 WinForms 作为兜底 |
| 多扩展共用一个 CLSID | SharpShell 多 Association；注册脚本一并更新 |
| TreeView 超大 JSON | 限制展开深度 / 节点数，超限降级为纯文本 |
