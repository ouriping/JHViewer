# 预览控件调试

`MarkdownPreviewControl` 可以调试。它跑在资源管理器的 `prevhost.exe` 里，不能对类库直接按 F5，要用「附加到进程」。

## 在 VS2022 里打开设计器

1. 用 VS2022 打开 `MarkdownContextViewer.sln`。
2. 在解决方案资源管理器中展开 `MarkdownPreview.Handler`。
3. 双击 `MarkdownPreviewControl.cs`，或右键该文件，选择「查看设计器」。
4. 工具栏按钮在 `panelToolbar` 里，预览区是 `panelPreview`。WebView2 只在运行时创建，设计器里看不到页面内容。
5. 改完按钮后保存。设计器只改界面，点击逻辑在 `MarkdownPreviewControl.cs` 的 `btn*_Click` 方法里。

## 附加到预览宿主

1. 菜单「生成」→「配置管理器」，平台选 **x64**，配置选 **Debug**，然后生成解决方案。
2. 运行主程序 `MarkdownContextViewer`，取消再勾选「资源管理器预览」，把新的 DLL 部署出去。
3. 打开文件资源管理器，按 Alt+P 打开预览窗格，选中一个 `.md` 文件，确认预览已经出现。
4. 回到 VS2022：「调试」→「附加到进程」。
5. 勾选「显示所有用户的进程」。代码类型选「托管」。
6. 在列表里找 `prevhost.exe`。可能有多个，选已加载 `MarkdownPreview.Handler.dll` 的那个：选中进程后点「选择」，或附加后在「调试」→「窗口」→「模块」里搜索 `MarkdownPreview.Handler.dll`。找错进程就分开，换下一个 `prevhost.exe`。
7. 在 `btnRefresh_Click`、`btnEditor_Click` 等处理方法里打断点。
8. 回到资源管理器，再点一次工具栏。断点应命中。

## 看操作日志

点击会写入下面两个路径之一（低完整性进程写第一个）：

- `%LocalAppData%Low\MarkdownContextViewer\preview-handler.log`
- `%LocalAppData%\MarkdownContextViewer\preview-handler.log`

点按钮后应出现类似：

```text
操作: 工具栏收到鼠标激活 actionStrip
操作: 点击 | 刷新 | file=D:\docs\readme.md
操作: 刷新完成 | D:\docs\readme.md
```

如果只有「鼠标激活」、没有「点击」，说明点击仍被预览宿主吃掉。如果连「鼠标激活」都没有，说明点到的是 WebView2 而不是工具栏。

## 改完代码后

`prevhost.exe` 会锁住已加载的 DLL。要重新生成：先在主程序点「结束预览宿主」，或在任务管理器结束 `prevhost.exe`，再生成并重新勾选预览。
