# Markdown 导出与网站访问功能设计说明

## 1. 目标

在现有 WinForms Markdown 编辑器基础上，新增两类能力：

1. **一键导出到程序运行目录并以网站方式访问**
2. **指定一个文档目录，按文件夹结构提供网站访问**

并确保：
- 本地可用、操作简单
- 不影响现有编辑流程
- 后续可扩展为局域网访问

---

## 2. 推荐实现方案（最佳实践）

推荐采用 **双模式 + 本地轻量 HTTP 服务**：

### 模式 A：一键导出当前文档（或全部已打开文档）

- 将 `.md` 转换为 `.html`
- 输出到程序目录下：`./site-output/`
- 自动生成 `index.html`
- 启动本地站点：`http://127.0.0.1:5088`

### 模式 B：开放指定文档目录为网站

- 用户选择一个目录（例如 `D:\docs`）
- 程序扫描目录树中的 `.md`
- 动态生成导航树页面
- 通过本地地址访问和浏览

> 推荐默认只绑定 `127.0.0.1`，更安全；需要时再开放到 `0.0.0.0`（局域网可访问）。

---

## 3. 为什么这是“最好”的方案

1. **易用**：对用户是“一个按钮”就能发布并浏览。
2. **风险低**：默认仅本机访问，不暴露公网。
3. **兼容现有结构**：只增加服务类，不破坏现有编辑控件。
4. **可扩展**：后续可加搜索、目录索引、主题、权限控制。

---

## 4. 代码结构建议

新增服务类：

- `SiteExportService.cs`
  - 输入：Markdown 文本或文件路径
  - 输出：`site-output` 目录下的 HTML 文件
  - 职责：
    - `.md -> .html`
    - 复制静态资源（CSS/JS）
    - 生成 `index.html` 导航页

- `LocalWebHostService.cs`
  - 职责：启动/停止本地 HTTP 服务
  - 推荐：`HttpListener` 或第三方轻量库（如 `EmbedIO`）
  - 提供：
    - `Start(rootPath, port, host)`
    - `Stop()`

- `SiteIndexBuilder.cs`（可选）
  - 职责：根据目录树生成导航 HTML（树状列表）

---

## 5. UI 改造建议

在主界面顶部新增分组（“发布”）：

1. `导出当前为网站` 按钮
2. `导出全部打开文档` 按钮
3. `选择目录并启动网站` 按钮
4. `停止网站` 按钮
5. 端口输入框（默认 `5088`）
6. “打开浏览器”按钮

提示信息建议：
- 导出成功路径
- 当前访问 URL
- 端口占用时的错误提示

---

## 6. 访问路径设计

建议统一规则：

- 首页：`/` -> `index.html`
- 文档页：`/docs/xxx.html`
- 静态资源：`/assets/...`

如果是目录模式：
- 保留目录结构映射，比如：
  - `D:\docs\A\B\readme.md`
  - 网站路径：`/docs/A/B/readme.html`

---

## 7. 实施步骤（落地顺序）

### 第一步（最小可用）
- 做“导出当前文档到运行目录”
- 自动打开默认浏览器访问 `index.html`

### 第二步（完整站点）
- 加本地 HTTP 服务
- 生成导航页 + 多文档访问

### 第三步（目录网站）
- 选择文档根目录
- 扫描并生成目录树导航

### 第四步（增强）
- 文件变更自动刷新（可选）
- 搜索索引（可选）
- 主题切换（可选）

---

## 8. 关键技术点

1. Markdown 渲染：沿用现有 `Markdig`。
2. HTML 模板：抽成统一模板（头部样式 + 内容容器）。
3. 路径安全：
   - 只允许站点根目录内文件访问
   - 禁止 `..` 路径穿越
4. 端口检测：启动前检查端口是否占用。
5. 编码统一：UTF-8。

---

## 9. 安全与发布建议

- 默认绑定：`http://127.0.0.1:5088`
- 如开放局域网，明确提示风险
- 不建议默认公网暴露
- 若需长期服务，建议独立为 ASP.NET Core 服务并加鉴权

## 11. 最终建议（结论）

**先做模式 A（导出并访问）作为 MVP，再扩展模式 B（目录网站）**。

理由：
- 开发快、价值高
- 用户马上可用
- 技术风险最低
